# 视觉目标卡 · 住院转科连带处置系统

> **本环境不具备图像生成能力，因此本轮只提供结构化视觉目标卡，不生成、不伪造任何概念图。**
> 真实运行截图在收尾阶段采集于 `docs/screenshots/`，见 README 的「概念 / 实测对照」。
> 本卡同时是 `src/itc/ui/tokens.py` 的取值依据（任务 13）。

---

## 0. 设计基调

对标**医院中后台工作台**（HIS 病区工作台 / 住院服务中心办理台），不是数据大屏、不是 demo 页。

- 浅底为主，信息密度中等偏上，表格是主工作面。
- 联动图**只作进度可视化**，用来让护士长看懂「这次牵动到哪儿了、卡在哪一步」；要看细节仍以逐条处置清单为准。
- 语义色只用于状态表达，不用于装饰；正文与表格用中性灰阶。
- 单屏主操作只保留一个 primary（未接单时是「拉取今日转科」，接单后是「导出交接核对单」）。

## 1. 三个状态

### 1.1 起始态（程序刚打开，尚无转科单）

- 中后台布局：左侧固定导航栏（宽 200px，浅灰底）+ 右侧主内容区。
- 页头区：页面标题「住院转科连带处置」+ 一句说明「HIS 下完转科单后，把转科单拖进来，当场算出牵动范围」+ 右侧 primary 按钮「拉取今日转科」。
- 内容区是**空态**：一个线性图标位（不是插画）、一句「今日暂无转科单」，下面两个次要入口「拖入转科单 JSON」「粘贴 JSON 文本」。
- 左下角一行状态摘要：「HIS 未连通 · 模型未连通」，灰字。

### 1.2 首个可用瞬间（拖入一张转科单，取数完成）

- 左侧导航选中「转科处置」，主内容区上半部是**联动图视图**（`QGraphicsView`）：节点卡横向排布 5 张 —— `转科单` → `取数` → `规则判定` → `模型判定` → `确认回写`，节点之间是带箭头的细连线；已执行节点卡左侧有一个 6px 圆点状态灯（灰=待执行 / 蓝=执行中 / 绿=已完成 / 橙=待人工 / 红=失败）。
- 下半部是**逐条处置清单表**（`QTableView`）：列依次为 `业务对象`、`判定`、`执行科室`、`证据片段`、`置信度`、`状态`；共 3 行。
- 状态列用**标签**而不是纯文字：`待确认`（琥珀底）、`待人工判定`（橙底）、`已回写`（绿底）。
- 表格上方一行筛选条：`全部 | 待确认 | 已回写 | 待人工`，右侧一个次要按钮「导出交接核对单」。
- 页面底部一行运行摘要：「取数 3 类 · 判定 7 条 · 阻断 1 条 · 用时 0.8s」。

### 1.3 成形态（逐条确认完成，含停嘱草稿条目）

- 联动图上「确认回写」节点卡转为已完成态并显示写回计数徽标 `7`。
- 清单里已确认的行状态标签变绿「已回写」；**涉及停嘱的那一行**状态标签是**灰底深字「草稿·需医师复核」**，该行的「确认」按钮为 disabled 且置灰，草稿正文以只读文本框展示并带「复制草稿」次要按钮。
- 一条「不可自动停嘱·需医师判断」的行以红字标注，无按钮。
- 托盘图标出现数字角标（待确认 0 / 待重试 1），鼠标悬停出提示气泡。
- 右下角 toast：「已写回 HIS 7 条，导出交接核对单交给病区」。

## 2. 视觉语言

### 2.1 色板（具体色值，`tokens.py` 必须落这些值）

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 primary | `#1B6AC9` | primary 按钮、选中态、进度中 |
| 主色 hover / pressed | `#15579F` / `#124A87` | 按钮四态 |
| 语义 success（已回写） | `#16A34A` | 状态标签底 `#DCFCE7` / 字 `#166534` |
| 语义 warning（待确认） | `#D97706` | 状态标签底 `#FEF3C7` / 字 `#92400E` |
| 语义 danger（失败 / 不可自动停嘱） | `#DC2626` | 状态标签底 `#FEE2E2` / 字 `#991B1B` |
| 语义 info（待人工判定） | `#2563EB` | 状态标签底 `#DBEAFE` / 字 `#1E40AF` |
| 中性 · 标题 | `#0F172A` | 页面标题与区块标题 |
| 中性 · 正文 | `#334155` | 正文、表格正文 |
| 中性 · 辅助 | `#64748B` | 说明文字、单位、状态摘要 |
| 中性 · 禁用 | `#94A3B8` | disabled 文字与描边 |
| 中性 · 分隔线 | `#E2E8F0` | 表格行分隔、表头下边线 |
| 中性 · 表头 / 斑马 | `#F1F5F9` / `#F8FAFC` | 表头底、偶数行底 |
| 页面底 / 卡片底 | `#F1F5F9` / `#FFFFFF` | 内容区底、表格与卡片底 |

### 2.2 间距与圆角

- 8px 栅格，只允许 `4 / 8 / 12 / 16 / 24 / 32`。
- 页面内边距 24；卡片内边距 16；表格单元格上下 8、左右 12；按钮内边距 8×16。
- 圆角：卡片 6px、浮层 / toast 8px、模态 12px。
- 阴影两级：卡片无阴影只靠描边；浮层 `0 4px 16px rgba(15,23,42,0.10)`。

### 2.3 字体族与层级

- 中文正文栈：`-apple-system, "PingFang SC", "Microsoft YaHei", "Source Han Sans SC", sans-serif`
- 等宽 / 数字栈：`"SF Mono", Consolas, "Courier New", monospace`，所有数字与住院号摘要用 `tabular-nums` 等宽对齐。
- 层级四级：页面标题 20px/600、区块标题 16px/600、正文与表格 14px/400、辅助说明 12px/400。

### 2.4 信息层级

1. 页面标题区（标题 + 一句说明 + 主操作）—— 唯一视觉焦点。
2. 联动图视图 —— 次级，用于理解流程与卡点，尺寸不超过内容区高度的 45%。
3. 逐条处置清单 —— 真正的数据面，占主要面积。
4. 底部运行摘要 —— 最弱，12px 辅助灰。

### 2.5 留白密度

- 表格行高 36px，列之间靠 1px 分隔线而非大量空白。
- 空态区域留白大（上下 48px），让「暂无转科单」这件事一眼可读。
- 不用大插画、不用渐变背景、不用阴影堆叠。

## 3. 必须可达的约束（只允许用当前依赖真能做出来的元素）

| 约束 | 说明 |
|---|---|
| 只用 PySide6 2D 控件 | `QMainWindow` / `QLabel` / `QPushButton` / `QTableView` / `QComboBox` / `QLineEdit` / `QSystemTrayIcon` / `QGraphicsView`（`QPainter` 画节点卡与连线）。**不画** WebGL / 3D / 粒子 / 视频 |
| 图标用内联 SVG 或 Qt 标准图标 | **禁止** emoji 当图标 |
| 无动画库 | 过渡只用 Qt `QPropertyAnimation` / CSS 式 `transition` 的简单淡入淡出（150–250ms） |
| 无前端框架、无 CDN | 不引入 Vue / React / Tailwind CDN；样式集中在 `tokens.py` 与样式表 |
| 不连真实 HIS 也能渲染 | 界面元素在模型服务与 HIS 均不可达时也必须能出（空态 + 错误态），不因取数失败白屏 |
| 截图可采集 | 界面须支持在无头/有头环境稳定渲染，真实截图由收尾阶段在样例数据上采集 |
